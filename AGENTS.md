# OpenVids

OpenVids is a standalone, agent-native desktop video editor derived from an initial HyperFrames snapshot.

## Architecture

- **Desktop Shell**: Tauri 2 (`apps/desktop`), shipping on macOS (`.app` + `.dmg`) and Windows x64 (NSIS per-user `*-setup.exe`, WebView2 download bootstrapper).
- **Frontend / Editor**: HyperFrames-derived Studio served from a local loopback HTTP server (`cli` launches the Studio server; SPA + `/api`; composition iframe).
- **Core Constraints**:
  - Studio and the composition iframe rely on same-origin synchronous DOM access. Never move Studio to `tauri://`, never introduce a second wrapper editor UI, and do not migrate off Tauri without a concrete blocker.
  - Project and source files on disk are the single source of truth.
  - Hard kills (SIGKILL, crash) are recovered, never cleaned up by handlers: history keeps open agent windows in `<history home>/open-windows.json` and files a dead owner's writes to the turn's own entry on the next start (so `Revert this turn` still works); the Studio server sweeps `renders/work-*` and `.*.hf-transaction-*` at start and the engine kills Chrome whose owner died (`<tmp>/hyperframes-browsers/<pid>.json`, `sweepOrphanBrowsers`). On macOS/Linux teardown is process groups + SIGTERM/SIGKILL; on Windows it is kill-on-close Job Objects in `apps/desktop/src-tauri/src/proc.rs` (`KILL_ON_JOB_CLOSE`, `CREATE_NO_WINDOW`), so quit and Task-Manager kills both reap bun/Chrome/ffmpeg, and the orphan sweep has a win32 `taskkill` path. The render queue is the same kind of state: tickets and the render slot are files in `~/.openvids/render-queue/` (`OPENVIDS_RENDER_QUEUE_DIR`) with a pid, a process start and a heartbeat, so a SIGKILLed render is evicted by the next waiter (pid gone or process start changed; where the start cannot be read cheaply, i.e. Windows, also no heartbeat for 3 min, and never right after this process itself was suspended) and frees the queue with no handler. A live, start-verified holder is never judged by heartbeat age (a sleeping machine stops every timer), a holder only refreshes a slot that names its own ticket, and a slot whose ticket is gone is evicted. Keep new long-lived state recoverable the same way.
  - Anonymous usage statistics are sent by the Tauri shell only (`apps/desktop/src-tauri/src/telemetry.rs`; gated by `telemetry.enabled`, `DO_NOT_TRACK`, `OPENVIDS_TELEMETRY`); Studio, `studio-server`, `agent-runtime` and `cli` never send them, and a new event or field lands only together with the README's "Usage statistics" section.
  - Bug reports are an explicit user action from the Tauri shell only (`apps/desktop/src-tauri/src/report.rs`, window label `report`): text, screenshots, an optional email and the redacted log tail leave the machine, the email and logs are never public, the text and screenshots become a public GitHub issue, and the telemetry preference/`DO_NOT_TRACK` do not apply to them. Docs never name the servers behind statistics and reports or how they are run.
  - Beta features are code on `main` that only a beta build turns on (none at the moment: 0.5.1 shipped project tabs, `#` mentions, design systems and voiceover on stable): the channel comes from the version (`0.5.0-beta.1` is beta, `apps/desktop/src-tauri/src/channel.rs`), debug builds count as beta, `OPENVIDS_BETA_FEATURES=1|0` forces it. The shell passes `openvidsChannel=beta` in Studio's URL (`packages/studio/src/betaFeatures.ts`, `isBetaFeatureEnabled(id)`) and `betaFeatures` in the Projects page's `OV_BOOT` (`OV.betaFeatures()`). Gate beta-only UI there; a feature leaves `BETA_FEATURES` when it ships on stable, and its gates and feature-off code paths are deleted then. Server-side code reads the flag from its environment: the shell sets `OPENVIDS_BETA_FEATURES=1|0` (normalised from `beta_features_enabled()`) on the Studio sidecar, which the agent runtime inherits, and `desktop:dev`'s `serve-studio-dev.mjs` sets it for the Vite server (`scripts/beta-env.mjs`); only the exact value `1` means on.
  - Update channels: `updates.channel` (`stable` default | `beta`; normalized identically in `apps/desktop/src-tauri/src/prefs.rs` and `packages/studio-server/src/app/preferences.ts`) picks what the updater reads (`apps/desktop/src-tauri/src/updater.rs`). Stable reads only `releases/latest/download/latest.json`; beta also reads `releases/download/channel-beta/beta.json` and offers the newer of the two, each manifest checked by its own updater (the plugin's `endpoints` are a fallback chain, not a "pick the newest") with `is_newer` strict semver precedence, never a downgrade. A tag with a pre-release version is a beta: `release.yml` publishes it as a GitHub pre-release with `beta.json` (never `latest.json`), and publishing it runs `beta-manifest.yml`, which copies `beta.json` to the `channel-beta` service release. Same signing key and app identifier, so betas and stable install over each other; turning the switch off drops a pending beta download but never rolls back. Only the shell's Settings (`/api/preferences`) writes `updates.channel`: Studio's `PUT /api/app/preferences` refuses it (`invalid_preferences.desktop_only`) because composition code can reach that route. The channel is never sent in usage statistics; if it ever is, update the README's "Usage statistics" in the same change.
  - Duplicate and Fork share one copier (`apps/desktop/src-tauri/src/project_copy.rs`; `POST /api/duplicate`, and `POST /api/fork` + `GET /api/fork/state` + `POST /api/fork/cancel` in `home_fork.rs`, one background job with byte progress and Cancel): the copy is built in a hidden sibling `.openvids-fork-<hex>` (marked with the builder's pid) and published by a no-replace rename that claims the final name (`X copy` / `X fork`), the builder's marker stays until the rename has published it, crash leftovers are swept at start (a marker-less temp folder only once it is 10 minutes old), and nothing derived is copied (`is_excluded`: `renders/`, `.transcode-cache`, `.hyperframes/{agent/usage.jsonl, agent/owner.pid*, agent/intake.json, history-id, history-turn(s).json, research/cache, qa/frames, qa/reports, preview, backup, prepared-assets}`, `*.lock.os`, `.*.hf-transaction-*`); assets, `design/`, story, provenance, ranges, analysis, `qa/accepted.json` and the chats are. `prepared-assets` is only a cache (animated GIFs re-encoded to WebM by content hash, remote GIF downloads): the project HTML keeps the GIF, and only the in-memory preview/render HTML points at the cache. A copy refuses to start while an agent turn runs (the open project's Studio `/activity`; a project another process serves is refused by its live `.hyperframes/agent/owner.pid` lease, judged by pid and recorded start like `processLock.ts` so a reused pid never blocks (`proc::start_key`/`same_start`, Windows via GetProcessTimes with the 10 s tolerance)). Lineage lives in `meta.json`: `uid` (given lazily when a project is first forked; every copy gets a new one, plus a fresh `createdAt`, name and `package.json` name) and, on a fork only, `forkedFrom { uid, name, dir, at }`, shown on the card as "Fork of X" (`recent_json.forked_from`). The copy's `.hyperframes/agent/fork.json` `{ forkedAt }` makes the agent runtime (`store/forkMarker.ts`) drop the checkpoints of older turns when it reads a chat, so there is no "Revert this turn" for work whose history entries stayed in the original (a past revert stays shown, without Undo); a rebuild of the usage journal from chat logs must skip those turns too.
  - Project tabs (the desktop's only window model; `AppState.tabs` in `apps/desktop/src-tauri/src/lib.rs`): several projects open in one window, each its own Studio sidecar on its own loopback origin and its own child webview (Tauri `unstable` multiwebview, `tab_webviews.rs`; the Projects page stays the window's own `main` webview, so `get_webview_window("main")` no longer answers: use `tab_webviews::main_window` / `main_webview`). `tabs.rs` is the per-project state keyed by `recents::project_key` (open gate per key, tab order, active tab), `project_open.rs` the open flow, `tab_actions.rs` activate / close (asks first when `updater::activity_of` says a render, incl. queued, or an agent turn runs) / soft limit of 6. The strip is drawn by the pages (Studio `components/shell/ProjectTabStrip.tsx`, Projects page `home_page/tabs.js`) from `GET /api/tabs` (`{ active, limit, tabs }`) on the home server (`home_tabs.rs`); Studio has no home token, so exactly `GET /api/tabs` and `POST /api/tabs/{activate,close,fork}` are granted token-free to live project origins (`studio_grant` in `home_routes.rs`). A tab's Fork button posts `POST /api/tabs/fork {key}`: the open tab's folder (`TabActions::project_dir`) is forked by the same `home_fork` job and refusals as the Projects page's Fork, and the window switches to the Projects page, whose `adoptFork` (home.js, also on reload) follows the copy with Cancel and opens the fork as a new tab. Per-project opening state is `HomeInner.opens` (`GET /api/open-state` `opens[]`). Quit takes every project out of `AppState` and reaps all sidecars in parallel.
  - `#` attaches other projects to a chat: a link, never a copy. A project is keyed by `recents::project_key`; the browser and the agents only ever see key + name, never a path. The Studio sidecar asks the Projects (home) server for the list and a key's folder through `GET /internal/projects[/key]` (`apps/desktop/src-tauri/src/home_internal.rs`), authenticated by a per-launch secret in the sidecar env (`OPENVIDS_HOME_URL`, `OPENVIDS_HOME_SECRET`; under `desktop:dev` Vite has no such env and re-reads `OPENVIDS_HOME_FILE` = `packages/studio/data/home-link.json`, written by the shell): those routes accept only that secret (never the home token), refuse any request that carries an `Origin`, and `studio-server`'s agent gateway strips all three variables from the runtime's env so agents cannot read them. `studio-server/src/crossProject/` (adapter capability `externalProjects`, routes `/api/projects/:id/cross-project/*`) builds the per-part summary without ffprobe (renders / music / other audio / images / video / story; music = a story node, a provenance record or the path tokens in `helpers/audioNameTokens.ts`, shared with `qa/timelineChecks.ts`), the manifest, and the cancellable import into `assets/from/<project>/` that carries the source's provenance record (`importedFrom`) under the research import's commit point. The runtime derives access per call from the `ProjectReference`s of the chat's user messages (`agent-runtime/src/crossProject/access.ts`, modelled on `research/linkedSites.ts`): `import_from_project` refuses any project, part or file that is not attached, and the turn's prompt carries an `<attached-projects>` manifest plus the story synopsis. The composer's `#` trigger is `packages/studio/src/agent/projectMentions.ts` + `components/chat/ProjectMentionMenu.tsx`.
  - The design-system library (`~/.openvids/design-systems`, `OPENVIDS_DESIGN_SYSTEMS_DIR`) is written by the Studio server and, for rename/delete and the new-project snapshot, by the Tauri shell (`design_library.rs`, `design_snapshot.rs`): both take `<root>/.lock`, the `ownerLock.ts` protocol (`design_lock.rs`; never evict a live pid's lock), and write byte-identical `<project>/design/` snapshots (`design.json` keys `schema,id,version,name,attachedAt,createdAt,unknownLicenses,nonPortableFonts`; `createdAt` is the library entry's lineage). Ids that are Windows device names (`con`, `nul`, `com1`…) are refused on every platform (`isDesignSystemIdText` / `is_design_id`). The new-project sheet also links `design/tokens.css` from `index.html` (compositions only pick a system up through that link); the Projects page reads thumbnails and showcases through the open, sandboxed `/design-files/<id>/…` GETs (see `apps/desktop/README.md`).
  - The Projects page's Design systems UI (`apps/desktop/src-tauri/src/home_page/design.js`, `design-sheets.js`) frames a system's showcase only as `<iframe sandbox="allow-same-origin">` (never add `allow-scripts`: the framed page must stay script-less; `allow-same-origin` keeps its font requests same-origin, so no design route, in the shell or in Studio, sends any CORS header and the shell's `home_auth` never grants an Origin beyond its own), and server text reaches its markup escaped, palette colors only after a strict pattern check.
  - Voiceover (cloud text-to-speech with the user's own key, no shared key): global state in `~/.openvids/voice/` (`OPENVIDS_VOICE_DIR`): `providers.json`, `api-keys.json` (0600, never served back, scrubbed from every error), `presets.json`, the request-hash audio `cache/` and an optional `pricing.json` over the shipped dated rates (`studio-server/src/voice/pricing.default.json`; never hard-code a price). The Studio server and the shell (`voice_settings.rs`, `home_voice.rs`) write the same files; the custom server's address is shell-only (Studio's route answers `desktop_only`, because composition code shares Studio's origin and could send the stored key elsewhere). Agents never pass an address or a key: they pick a preset the user saved and send lines. Paid calls start only after the dialect check passed and the user allowed `voice_generation` in that turn; the voice tools are refused in Ask turns, every Render QA phase and after a plan proposal. The Gemini connector was run against the live API; the OpenAI-compatible and ElevenLabs connectors were written from the vendors' documentation only.

## Windows notes

- Custom frameless window (`decorations(false)`; the pages draw minimize / maximize / close); `OPENVIDS_SYSTEM_FRAME=1` falls back to the OS frame. No visible menu bar on the custom frame: the native menu exists for its `Ctrl+` accelerators (`Ctrl+O` / `Ctrl+Shift+O` / `Ctrl+R`, mirrored as in-page handlers) plus the system-frame fallback. `Ctrl+,` (Settings) is not a native accelerator: it works only through the in-page handlers (`apps/desktop/src-tauri/src/home_page/home.js`, `packages/studio/src/hooks/useOpenvidsDesktopShortcuts.ts`).
- FFmpeg is not bundled. Resolution order: an explicit `HYPERFRAMES_FFMPEG_PATH` / `HYPERFRAMES_FFPROBE_PATH` in the environment, then the copy the app's download button installed (`managed_env()` points every child at it and prepends it to `PATH`, so it beats an FFmpeg on `PATH`), then `PATH`. The button fetches the official gyan.dev essentials build into `%USERPROFILE%\.openvids\ffmpeg` (`ffmpeg_install.rs`, applied per spawn via `managed_env()`). The archive URL and its SHA-256 are pinned in the binary, the whole download-and-swap holds an exclusive `ffmpeg.lock`, and an install that a crash or kill interrupted is recovered at the next start (`recover_managed_install`) before any sidecar runs: the newest complete backup is restored, never the only complete copy deleted.
- Rust `home_dir()` resolves exactly like Node `os.homedir()` (`USERPROFILE` on Windows), so `~/.openvids` is the same directory on both sides.
- Drops onto the Projects page are file-picker-only in v1 (`drop_paths.rs` has no Windows pasteboard equivalent); copy says Explorer / Recycle Bin via `.win` locale keys. `stage-runtime.mjs` stages `bun.exe` + win32-only natives and strips `*.map`/`*.d.ts` (except the `declarations.d.ts` files the OMP SDK imports as text) for `MAX_PATH` headroom under the NSIS per-user install dir. CI runs macOS + Windows; symlink-based tests skip without Developer Mode / elevation.

## Package Manager & Commands

OpenVids uses **Bun** (not pnpm or npm).

```bash
bun install               # Install dependencies
bun run desktop:dev       # Launch desktop application in development mode
bun run desktop:build     # Build desktop application release bundle
bun run desktop:check     # cargo check for the Tauri shell (no TypeScript typecheck; use bun run typecheck)
bun run build             # Build workspace packages
```

### Linting & Formatting

Uses **oxlint** and **oxfmt** (not eslint, not prettier, not biome):

```bash
bunx oxlint <files>        # Lint
bunx oxfmt <files>         # Format
bunx oxfmt --check <files> # Check formatting
```

## Packages & Directories

### Packages (`packages/`)

- `core`: Types, parsers, generators, linter, runtime, frame adapters, HTML bundler, and the shared timeline-asset markup builder (`@hyperframes/core/editing/timeline-asset`) used by Studio drops and the agent editing service. The runtime's preview media budget (`src/runtime/previewMediaBudget.ts`) keeps at most 16 `<video>` elements with a loaded source around the playhead in Studio preview documents only (never in render/capture), and starts `<audio>` clips (served with `preload="none"`, `src` kept) loading only near the playhead, a few at a time; code that reads a preview video's `src` must use `readPreviewMediaSrc`.
- `parsers`: HTML/CSS parser utilities and subcomposition path rewriters.
- `lint`: Static analysis and HTML composition lint rules.
- `studio-server`: Local HTTP loopback server powering preview, state, file observation, undo/redo history, the agent gateway, the machine-wide render queue (`src/render/renderQueue.ts`: one render at a time across every Studio server and the agent; `POST /projects/:id/render` answers `rendering` or `queued` with `queuePosition` (1 = next) and `queueHolder.projectName`, the progress SSE carries both, cancelling a queued job gives up its ticket, `/activity` counts queued renders as active, the slot is freed when the adapter job's optional `finished` promise settles), the agent editing service (`src/editing/`, `/api/projects/:id/editing/*`; the user's picked asset fragments live in `.hyperframes/media/ranges.json` behind `/api/projects/:id/editing/ranges`, are history-tracked, and bind every non-Studio placement), the long-form analysis service (`src/analysis/`, `/api/projects/:id/analysis/*`: durable per-source artifacts in `<project>/.hyperframes/analysis/`, invalidated by source content hash, input versions and algorithm recipe; orphaned artifacts of deleted files and their cut plans are swept, and a plan's `applied` state is derived from the `data-ov-cut` clips on the timeline), the Story service (`src/story/`, `/api/projects/:id/story/*`: the Story Graph in `.hyperframes/story/graph.json`, user saves with authorship, agent edits that never override locks or the user's decisions, the deterministic intent compiler (`compile.ts`) and the Story ↔ timeline sync planner (`sync.ts`) behind full Build Story and Rebuild affected sections; built clips carry `data-ov-story-node` / `data-ov-cut` / `data-ov-turn` provenance, and the sync ledger `.hyperframes/story/sync.json` records which clips each section/unit owns and their generated state, so manual edits are found by structured comparison, never by diffing HTML), the Research service (`src/research/`: the global Asset Search policy at `/api/research/*` in `~/.openvids/research/policy.json` (`OPENVIDS_RESEARCH_DIR`), and per project `/api/projects/:id/research/*` search/inspect/import/resolve/sources/export-check, plus the website style reader `POST /api/projects/:id/research/website` (`src/research/website.ts`): for a public http(s) page the user linked, headless Chrome renders it inside the CLI child `cli inspect-site <url> --json --out <dir>` (`packages/cli/src/siteInspect/`, adapter `inspectWebsite` in `server/siteAdapter.ts`; never in the server process, Chrome runs over a pipe with an isolated temp profile, no downloads, a 30 s budget, and all of its traffic (loopback included, QUIC off) goes through the CLI's local vetting proxy `siteProxy.ts`, which resolves each host once through the request policy, applies the public-address rules to every tunnel and request, including WebSocket handshakes and workers, and connects only to the vetted addresses, so Chrome never resolves names itself; Studio also passes the user-linked sites as `allowedSites` and refuses any redirect hop or final address outside them before fetching further or writing; aborting the HTTP request or `requestId` cancel kills the child and its Chrome) and the answer is a `WebsiteStyle` (palette by role, fonts with source Google/self-hosted/system, type scale, radii, shadows, buttons, design tokens, motion hints, logo, headings) plus a 1440×900 and a ≤1440×3000 JPEG screenshot. The setting `websites.readLinkedPages` (default on, in the same `policy.json`, served and changed through `GET`/`PUT /api/research/policy`) must be on or the route answers 403 `blocked_by_policy`; the address rules (public hosts only, shared with Asset Search through the `@hyperframes/studio-server/public-address` subpath: `src/research/sources/address.ts`) are applied to the URL and, in the child, to EVERY request Chrome makes (redirect hops, CSS, fonts, images from any host) and to the address each connection really used, and the renderer sandbox stays on (`--no-sandbox` only for a root user on Linux, who cannot have it) while sockets, EventSource, WebRTC, popups and service workers are switched off in every document. Which sites an agent may ask for (only those the user linked in the chat) is enforced by the agent runtime, not here. `save: true` writes the screenshots, the logo (SVG sanitized) and the self-hosted font files the page loaded into `assets/web/<host>/`, each with an `AssetProvenance` record (source `website`, mediaKind `picture`/`font`, license unknown) in `.hyperframes/research/provenance.json`, through the same cancel commit point as imports; with full access on (`websites.fullAccess`), `/api/projects/:id/research/website/file` downloads any file a linked site serves or its pages load into `assets/web/<host>/files/` (or returns a page/style/script's text) and `/api/projects/:id/research/website/record` records a page as an MP4 into `assets/web/<host>/recordings/` through `adapter.recordWebsite`, both 403 `blocked_by_policy` while it is off and both still held to the public address rules on every request and redirect hop, and a per-turn grant kept in memory (`POST /api/projects/:id/research/website/grants`, `DELETE …/website/grants/:turnId`) lets that turn's website requests pass the check) and the render QA service (`src/qa/`, `/api/projects/:id/qa/*`: project fingerprint, deterministic checks of a RENDERED file — ffmpeg black/freeze (only where the source moves)/audio holes and silence, timeline flash clips/gaps/clips past their media/missing files/cuts inside a word (only for sources that carry speech: not music/sfx paths, not negligible speech, not annotation words, tolerant at pauses), layout through the CLI `check` child via `adapter.checkLayout` — Vision sample planning with what is on screen and said, frames of renders, `POST …/qa/check-timeline` (the timeline checks alone: no render is read, the render-measured checks answer `skipped`, no samples), immutable reports in `.hyperframes/qa/reports/` whose `current` flag is derived from the fingerprint and whose `renderAvailable` / `acceptedIssueIds` are derived when read, never stored, and the issues the user marked intentional in `.hyperframes/qa/accepted.json` (`GET`/`POST …/qa/accepted`, `DELETE …/qa/accepted/:acceptedId`; a damaged file reads as empty, retention never touches it); same-kind issues merge only when their times overlap; outside history). The Research service is the only place imported research assets touch the network: every connector search, page read and download into `assets/research/` goes through `sources/policyFetch.ts`, which checks the policy (trusted mode: enabled trusted sources only) and SSRF rules on every redirect hop (not covered by that policy: web search, a plain `fetch` allowed in both modes in `sources/webSearch.ts`; the render pipeline's downloads of remote media and Google Fonts; and the font catalog in `routes/fonts.ts`); sources are data (connector + domains) served by connectors under `sources/connectors/`; imports land in `assets/research/` with a provenance record in the history-tracked `.hyperframes/research/provenance.json` and bytes in the download cache `.hyperframes/research/cache/` (outside history); imports/resolutions carry a `requestId` and are cancelled at one commit point (`requestRegistry.ts`, `POST …/research/requests/:requestId/cancel`), so Stop never lets a write land after the turn's checkpoint. Agent `edit_timeline` batches carry the turn id: changed clips get a `data-ov-ai-edit` stamp so later AI edits are told from the user's. Editing-service, agent story and research writes are unclaimed outside edits: Studio live-reloads timeline writes and history attributes them to the running agent turn (the graph, ledger and provenance files are history-tracked but kept out of the preview signature and reloads). Speech recognition, diarization and the layout check run in CLI child processes (`adapter.transcribeMedia` / `diarizeMedia` / `checkLayout`, `cli/src/server/cliChild.ts`), never in the server process; the embedded CLI server forwards each request's abort signal, so a disconnect cancels the work.
  - Asset Search API keys: the built-in sources whose API needs one (Pexels, Pixabay, Flickr, Freesound, Smithsonian; `TrustedSource.apiKey`) search only with the user's own key, saved through `PUT`/`DELETE /api/research/sources/:id/api-key` into `~/.openvids/research/api-keys.json` (owner-only, also written by the Projects page in `research_policy.rs`), never served back, sent only to that source, removed from error messages, and a candidate whose URLs would carry it is dropped. OpenVids ships no shared key. Hosts that need their own header on every request (the Art Institute of Chicago's `AIC-User-Agent`, ccMixter's Referer) are listed in `SITE_HEADERS` in `sources/policyFetch.ts`.
  - Design-system library core (`src/design/`, routes in `routes/design.ts`: `/api/design-systems`, list/get/files/PUT/PATCH/DELETE; project routes are separate): agents write only a `DesignSystemSpec`, `renderDesignSystem` generates `system.html` (`:root` tokens, `@font-face`, embedded `<script type="application/json" id="openvids-design-manifest">`, CSS-only samples), `tokens.css` and `thumbnail.svg`, and `validateDesignSystemHtml`/`validateTokensCss` (strict tag/attribute allow-list, no script but the data block, no external URL anywhere, font sources only relative `fonts/`, the 18 contract tokens) gate every save; `parseDesignSystemHtml` reads a saved system back to its spec. `DesignLibrary.save` resolves fonts and the logo before taking the lock (Google Fonts via an injectable fetcher from `fonts.googleapis.com`/`fonts.gstatic.com` only, project files path-checked, ≤ 8 MB, extension + magic bytes, no symlinks, SVG logos refused if they script or reach out; an unchanged font or logo keeps its stored files on edit), then under `withLibraryLock` (`<root>/.lock` via `takeOwnerLock` in `history/ownerLock.ts`, in-process queue first) writes `versions/<n>/` complete (staging folder, `version.json` last, rename) and only then materialises the top level with `meta.json` last; a locked write or `heal()` re-materialises a top level that is behind its newest version and sweeps `.staging-*`/`*.tmp`. Reads are lock-free; `currentDir`/`versionDir` return the immutable `versions/<n>` folder, so copying from it never sees a half-switched top level. Files of a system or of a project's snapshot are served with `Content-Security-Policy: sandbox allow-same-origin; default-src 'none'; style-src 'unsafe-inline'; font-src 'self'; img-src 'self' data:` and no `Access-Control-Allow-Origin` anywhere (the showcase iframe is `sandbox="allow-same-origin"`, never `allow-scripts`, so its font requests are same-origin and no script can run); `/api/projects/:id/design/files/*` serves only `projectSnapshotFiles` (other files under `design/` are the user's). SVG logos are refused unless both a plain-text scan (denied tags/handlers anywhere in the bytes) and an XML read (`logoSvg.ts`) are clean, because an HTML parser reads `<title>`/`<style>` as raw text where a browser's XML parser does not. A missing project file is `null` for the resolver (so an edit keeps the stored logo/font it names by its library path); an edit may omit `name` (the current one is kept, a rename made meanwhile is not undone) and send `baseCreatedAt` (a system deleted and created again under the same id is a `conflict`, as version numbers start over). A project snapshot records the library entry's `createdAt` in `design/design.json` (after `attachedAt`) and counts a different `createdAt` as an update; the staging folder of an attach/update ends with a `previous.json` record (`{previous, incoming}`) and recovery finishes the swap from that record, never from what is left in the folder (a crash after some renames keeps every installed file), falling back to the listing for the shell's staging folders.
  - Design systems in a project (`routes/projectDesign.ts`, `design/snapshot.ts`, `design/extract.ts`, `design/palette.ts`): `PUT /api/projects/:id/design {id}` copies the library's current version into `<project>/design/` (`system.html`, `tokens.css`, `fonts/`, logo, `design.json` = `{id, version, …}` last; staged in `.hyperframes/design-staging-*` and swapped in, a crash is rolled forward or discarded at the next call), `POST …/design/update` is the only way a newer library version reaches the project, `DELETE` removes exactly the files the snapshot wrote; none of them touches a composition. ## Composition Conventions

- **HTML Structure**: Compositions are HTML files with `data-*` timing attributes.
- **Clips**: Clips need `class="clip"`.
- **GSAP Timelines**: Register one paused GSAP root timeline per composition on `window.__timelines`. Scene timelines manually added to that root must not be paused, or they will not advance when the root is seeked.
- **Deterministic Rendering**: No `Date.now()`, no unseeded `Math.random()`, no render-time network fetches.
- **TypeScript**: Avoid `any` and `as T` type assertions. Prefer type guards, predicates, and proper narrowing.
